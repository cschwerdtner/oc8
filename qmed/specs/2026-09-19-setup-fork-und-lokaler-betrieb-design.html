oc8: Fork & lokaler Betrieb

Aufbau des Forks, lokale Laufzeitumgebung und Update-Weg von Upstream.

Datei: qmed/specs/2026-09-19-setup-fork-und-lokaler-betrieb-design.html Status: umgesetzt Quelle: Session „oc8"

1 · Ziel & Kontext

oc8 ist ein Open-Source-Tool zum Orchestrieren von Agents (LGPL-3.0, oc8-ai/oc8). Wir wollen es lokal betreiben und gezielt erweitern, ohne den Anschluss an Upstream-Updates zu verlieren.

2 · Lösung

  • Repo: Fork cschwerdtner/oc8, lokal unter ~/claude/oc8. Remotes: origin = Fork, upstream = oc8-ai/oc8.
  • Branches: main bleibt identisch mit Upstream, eigene Arbeit auf qmed. Update: git fetch upstream && git checkout main && git merge --ff-only upstream/main && git checkout qmed && git merge main.
  • Eigene Dateien nur unter qmed/ und thoughts/ (plus .githooks/, .spec-wiki.json, .doc-wiki.json). Upstream-docs/ und scripts/ bleiben unberührt.
  • Laufzeit: Colima (kein Docker Desktop), Profil default mit 6 CPU / 8 GB. Start: colima start, dann ./scripts/quickstart.sh im Repo.
  • Modus: Dev (OC8_QUICKSTART_MODE=dev): Seed-Daten + Login ohne Passwort, nur localhost. Secrets liegen in .env (gitignored).
  • Localhost-Bindung: in .env OC8_HTTP_PORT=127.0.0.1:80 und OC8_HTTPS_PORT=127.0.0.1:443. Ohne das veröffentlicht Colima Port 80/443 im ganzen LAN.
  • Compose-Dateien: COMPOSE_FILE=docker-compose.yml:docker-compose.dev.yml:qmed/compose.qmed.yml in .env — jedes docker compose … lädt damit Dev-Modus und Q-MED-Overlay. quickstart.sh übergibt eigene -f-Flags; danach einmal docker compose up -d.
  • LLM: Ollama auf dem Mac (Apple-GPU), nicht im Container. OC8_OLLAMA_BASE_URL=http://host.docker.internal:11434, Modell qwen3:30b-a3b. Fallback-Modell via OC8_DEFAULT_MODEL im Overlay. Kein Cloud-Key gesetzt.
  • ACME-Seed angepasst: Ollama-model_config auf qwen3:30b-a3b, alle 16 ACME-Agents darauf umgehängt (nur DB, nach oc8 seed --reset neu nötig).
  • 2026-09-19 Caddy nur auf 127.0.0.1 binden (über .env)

    Nach dem ersten Start war der Dev-Login ohne Passwort unter 192.168.2.65 aus dem LAN erreichbar, weil Colimas Portforwarder auf *:80 bindet. Das Upstream-Compose liest OC8_HTTP_PORT/OC8_HTTPS_PORT, also reicht 127.0.0.1:80 in .env und Upstream-Dateien bleiben unverändert. Geprüft: LAN-IPv4 und öffentliche IPv6-Adressen liefern keine Antwort, 127.0.0.1 und ::1 liefern 200.

    Quelle: Session „oc8"

  • 2026-09-19 Lokales LLM über Ollama statt Anthropic-API oder Claude-Abo

    Die API ist Christoph zu teuer. Ein Claude-Abo lässt sich nicht nutzen: Die Claude-Code-Runtime von oc8 geht über das eigene /llm-Gateway mit API-Key, und Abo-Logins sind laut Anthropic nicht für Fremdtools gedacht. Ollama war schon installiert, kostet nichts und hält die Daten lokal.

    Quelle: Session „oc8"

  • 2026-09-19 qwen3:30b-a3b auf dem Host-Ollama, nicht im Ollama-Container

    Mixture-of-Experts mit ~3B aktiven Parametern, also schnell, und das Modell kann Tools aufrufen. Im Colima-Container gäbe es keine GPU, auf dem Mac läuft es über Metal. Geprüft: Tool-Aufruf über den oc8-ModelRouter in ~4 s, direkt und über den Claude-Fallback.

    Quelle: Session „oc8"

  • 2026-09-19 Eigenes Compose-Overlay qmed/compose.qmed.yml + COMPOSE_FILE in .env

    OC8_DEFAULT_MODEL wird vom Upstream-Compose nicht durchgereicht, der Fallback lief deshalb auf das nicht installierte mistral:latest (404). Ein Overlay statt einer Änderung an docker-compose.yml hält Upstream-Merges sauber. COMPOSE_FILE sorgt nebenbei dafür, dass der Dev-Modus beim Neustart nicht vergessen wird.

    Quelle: Session „oc8"

  • 2026-09-19 Fork statt reinem Clone, eigene Arbeit auf Branch qmed

    Erweiterungen sind geplant. Mit dem Fork sind sie versioniert und gesichert, main bleibt sauber und Upstream-Updates lassen sich mergen.

    Quelle: Session „oc8"

  • 2026-09-19 Eigene Doku/Tooling unter qmed/ statt docs/ und scripts/

    Upstream nutzt docs/ und scripts/ selbst. Ein eigener Top-Level-Ordner hält Merges von Upstream konfliktfrei. Der Kit-Pre-Commit-Hook wurde dafür auf qmed/scripts und qmed/docs umgebogen.

    Quelle: Session „oc8"

  • 2026-09-19 Colima statt Docker Desktop, 6 CPU / 8 GB

    Docker Desktop ist nicht installiert, Colima schon. Die Standardwerte von 2 CPU / 2 GB reichen für Postgres, MinIO, Redis, das Backend und den Frontend-Build nicht.

    Quelle: Session „oc8"

  • 2026-09-19 Quickstart im Dev-Modus

    Mit Seed-Daten und ohne Login-Hürde geht das Entwickeln am schnellsten. Nur auf localhost, nie ins Netz exponieren. Für produktive Nutzung später Community-Modus.
