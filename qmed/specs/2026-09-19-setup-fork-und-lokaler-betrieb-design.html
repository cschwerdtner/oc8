oc8: Fork & lokaler Betrieb

Aufbau des Forks, lokale Laufzeitumgebung und Update-Weg von Upstream.

Datei: qmed/specs/2026-09-19-setup-fork-und-lokaler-betrieb-design.html Status: umgesetzt Quelle: Session „oc8"

1 · Ziel & Kontext

oc8 ist ein Open-Source-Tool zum Orchestrieren von Agents (LGPL-3.0, oc8-ai/oc8). Wir wollen es lokal betreiben und gezielt erweitern, ohne den Anschluss an Upstream-Updates zu verlieren.

2 · Lösung

  • Repo: Fork cschwerdtner/oc8, lokal unter ~/claude/oc8. Remotes: origin = Fork, upstream = oc8-ai/oc8.
  • Branches: main bleibt identisch mit Upstream, eigene Arbeit auf qmed. Update: git fetch upstream && git checkout main && git merge --ff-only upstream/main && git checkout qmed && git merge main.
  • Eigene Dateien nur unter qmed/ und thoughts/ (plus .githooks/, .spec-wiki.json, .doc-wiki.json). Upstream-docs/ und scripts/ bleiben unberührt.
  • Laufzeit: Colima (kein Docker Desktop), Profil default mit 6 CPU / 8 GB. Start: colima start, dann ./scripts/quickstart.sh im Repo.
  • Modus: Dev (OC8_QUICKSTART_MODE=dev): Seed-Daten + Login ohne Passwort, nur localhost. Secrets liegen in .env (gitignored).
  • Localhost-Bindung: in .env OC8_HTTP_PORT=127.0.0.1:80 und OC8_HTTPS_PORT=127.0.0.1:443. Ohne das veröffentlicht Colima Port 80/443 im ganzen LAN.
  • Neustart im Dev-Modus: docker compose -f docker-compose.yml -f docker-compose.dev.yml up -d (ein nacktes docker compose up startet ohne Dev-Overlay).
  • 2026-09-19 Caddy nur auf 127.0.0.1 binden (über .env)

    Nach dem ersten Start war der Dev-Login ohne Passwort unter 192.168.2.65 aus dem LAN erreichbar, weil Colimas Portforwarder auf *:80 bindet. Das Upstream-Compose liest OC8_HTTP_PORT/OC8_HTTPS_PORT, also reicht 127.0.0.1:80 in .env und Upstream-Dateien bleiben unverändert. Geprüft: LAN-IPv4 und öffentliche IPv6-Adressen liefern keine Antwort, 127.0.0.1 und ::1 liefern 200.

  • 2026-09-19 Eigene Doku/Tooling unter qmed/ statt docs/ und scripts/

    Upstream nutzt docs/ und scripts/ selbst. Ein eigener Top-Level-Ordner hält Merges von Upstream konfliktfrei. Der Kit-Pre-Commit-Hook wurde dafür auf qmed/scripts und qmed/docs umgebogen.

  • 2026-09-19 Colima statt Docker Desktop, 6 CPU / 8 GB

    Docker Desktop ist nicht installiert, Colima schon. Die Standardwerte von 2 CPU / 2 GB reichen für Postgres, MinIO, Redis, das Backend und den Frontend-Build nicht.
